# Changelog: Device Intake Station

Covers: device intake cataloguing flow, quality questions at intake, netboot architecture, Phase 1/2 separation, scan.txt.

## 883. ✅ Intake item creation now emits a `Created` event
**Why:** Intake creates the `items` instance directly in `intake-answer.ts` `ensureItem` (via `persistItemInstance`), bypassing `add-item`/`import-item`, which are the only paths that call `logEvent`. As a result intake-born items had a completely empty audit trail: they appeared "out of nowhere," were absent from the recent-activity/event views, and (if their `Auf_Lager` later hit 0) were findable only by searching the exact Artikelnummer while invisible in default lists. Fix mirrors `import-item`'s convention exactly — a single `logEvent({ EntityType: 'Item', EntityId: itemUUID, Event: 'Created', Actor: 'intake-station', Meta: { source: 'intake', artikelNummer, serial, mac } })` right after the instance is persisted. `Created` resolves to level `info`/topic `logistics`, so it passes the default `listEventsForItem` level/topic filters and shows on item detail. Logged only on the create branch of `ensureItem`, so re-intaking an existing serial/MAC does not spam duplicate events; `logEvent` swallows its own errors, so logging can never break the intake flow.
**Deferred:** The other issues surfaced while investigating this report were left out of scope by the requester and are recorded in `todo.md`: (1) Artikelnummer padding mismatch — intake stores unpadded `"19503"` while `material-number.ts` stores 6-digit `"019503"`; (2) non-atomic `MAX(...)+1` allocation in `getMaxArtikelNummer` (race → colliding numbers / merged refs); (3) `ensureItem` re-intake trap — a `newRef` re-run allocates+creates a new ref but leaves the instance pointing at the old Artikelnummer, orphaning the new ref; (4) no operator-facing way to see items hidden by the list's `Auf_Lager > 0` filter. Intake also still logs no event for ref creation or quality completion — only instance creation is covered here.

## 845. ✅ Device Intake Station API — 4 endpoints + Phase 2 file upload support
   - **Why:** Alpine Linux netboot image on donated devices needs a minimal API to catalog items without a full UI. State machine routes each device boot to the correct step (select_ref → quality → phase2) based on DB state, so already-completed steps are skipped automatically. Phase 2 test results upload via the existing external-docs endpoint with SN:/MAC: prefix to bypass the DB lookup before item creation.
   - **Deferred:** scan.txt augmentation of agentic extraction prompt (reading Phase 2 scan results before the agentic run starts); operator notification on completion; InstanceSpecs sync across ref-sharing instances. These are v2 concerns that don't block the core flow.
