## Recent changes (last 10)

963. ✅ **Auto-approve now gates on findings, not confidence (lever L3).** The `AUTO_APPROVE` gate was keyed on the model's self-reported extraction confidence (unreliable); repointed it to **findings-clean** — a run auto-approves only when it has no `block` (missing-required) or `warn` (banned phrase / intake conflict) finding; info-level style hints tolerated (raise a rule's severity to gate). New pure `isAutoApprovable(findings)` in `findings.ts`; `item-flow` now computes findings first (on the wording-cleaned output) then the gate — so it **implicitly requires the wording pass** (fluffy prose leaves warn findings → no auto-approve). `AUTO_APPROVE` flag + `auto_approved` settle unchanged; `AUTO_APPROVE_MIN_CONFIDENCE` deprecated (no longer gates). Tests 246/246; tsc clean. → [agentic]
962. ✅ **`try-wording` harness — test the wording stage without full runs.** `scripts/try-wording.ts` (`npm run try:wording [-- item.json]`) builds the same Ollama client as the pipeline, loads the real `wording` prompt, and runs `runWordingStage` on a built-in messy fixture (banned phrases + fluff + English/odd spec keys) or a supplied item JSON — printing input → rewrite (Artikelbeschreibung/Kurzbeschreibung/tidied Langtext) + elapsed ms. Lets prompt/standards tuning happen in seconds instead of restart-a-run. Also confirmed the earlier timeout: the wording step's 20s per-stage cap was killing runs; removed it so it's bounded by the global 10-min model HTTP timeout like extraction. → [testing]
961. ✅ **Wording step after extraction (lever L2b).** A dedicated LLM pass (`flow/item-flow-wording.ts` `runWordingStage`) runs after extraction and **rewrites** the prose fields (`Artikelbeschreibung`/`Kurzbeschreibung`) into the house style + tidies `Langtext` spec key names — stripping marketing fluff and source-copied phrases ("mit einer Garantie von…") per `contracts/standards.json`, without changing facts. Extraction stays fact-oriented; wording owns style (the operator's shape). New `prompts/wording.md`, registered in `loadPrompts`. A **normal always-on stage** (no flag — consistent with extraction/supervisor/pricing; only autonomous behaviors are flagged); skipped in rework mode; failure/timeout keeps extraction's wording (never blocks). Tests `item-flow-wording.test.ts`; full agentic suite green; tsc clean. First real mechanic off the levers plan. → [agentic]
960. 🔧 Planning reset: **agentic review levers** (`PLANNING_agentic_levers.md`). The AI-data-quality planning had drifted into a from-scratch redesign (six pillars, new objects, a Workbench, an instance flow) — unbuildable as one step for a live pipeline. Reframed: `PLANNING_ai_data_quality.md` is now the **target/north-star**, and the new doc is the **working plan** — the smallest changes to the *existing* pipeline that move toward it, each anchored to a file that ships today (discipline: no lever without existing code). Inventories the machinery we already have (extraction, supervisor + `{{SUPERVISOR_REVIEW}}` slot, guidance injection, findings engine, `ambiguousFields`, auto-approve flag, contract-audit sweeper, reject-feedback loop, snapshots) and lists levers L1–L9 (scope tag on findings, standards→prompt prevention, auto-approve on zero findings, legible sweeper, per-finding actions, supervisor emits findings, exemplar findings on read, reject-feedback→standards, run provenance) ordered by leverage. Workbench / quality-grade formula / full reconcile flow / LLM auditor explicitly parked as emergent target-state. → [docs-infra]
959. ✅ **Findings now computed from current content on read (fix: re-run wiped the test phrase).** #930 computed findings from the run's *output*, so re-running an item regenerated the description before the scan → injected "mit einer Garantie von" vanished → no findings, and findings went stale on any manual edit. New `computeReferenceFindings(ref)` scans the item's **current** stored Artikelbeschreibung/Kurzbeschreibung/Langtext + missing-required; `getAgenticStatus` attaches them as transient `AgenticRun.CurrentFindings` on every read, and the frontend shows those. Editing an item to contain a banned phrase now shows the finding immediately, no re-run. Intake-conflict findings still run-time-only (need instance data). Tests 238/238 + reference-findings 5; tsc clean. → [agentic]
958. ✅ **"Zu prüfen" findings panel in the KI tab + review wizard (Session B start).** Each run's machine-computed findings (from `agentic_runs.FindingsJson`, #957) are now surfaced so reviewers know *what to check* instead of clicking blind. Shared `FindingsPanel` component renders a "Zu prüfen (N)" list (severity badge + field + message + evidence, worst-first) in **two places**: **persistently in the KI tab** (below the status card, visible on any run that has findings) and **in the review wizard** above every step (+ "zu prüfen" markers on flagged Spezifikationen rows). `ItemDetail` parses `FindingsJson` once (memo; malformed → no findings). Findings only populate on runs completed **after** #957 (no backfill) and an empty set hides the panel. Styles in `styles.scss`; wizard tests + existing green; tsc clean. Verified-collapse + per-finding bounded-ask interactions are next. → [ui]
957. ✅ **Review findings engine + wiring (Session A — review-by-exception foundation).** New deterministic, LLM-free `buildFindings()` (`backend/agentic/findings.ts`) + `Finding`/`StandardsContract` model (`models/agentic-findings.ts`) + runtime-editable rule set (`contracts/standards.json`, via `registry.getStandardsContract()`). Emits ranked **findings** from three producers: **banned/source-copied phrases** ("mit einer Garantie von…", "Im Lieferumfang enthalten…" — unwanted for second-hand), **missing-required** spec fields, and **intake conflicts** (extracted vs. measured, surfaced as a `choose`). Each finding carries a bounded ask (fix/choose/confirm/drop) + evidence + ruleId, worst-first. **Now wired end-to-end:** `item-flow` computes findings from the same `specCtx` signals auto-approve uses + a banned-phrase scan over the output text; persisted to a new additive `agentic_runs.FindingsJson` column (via `upsertAgenticRun`, COALESCE-preserving on non-computing paths, `"[]"` overwrites stale); exposed on `getAgenticRun` for the review UI (Session B). Engine unit-tested 8/8; full agentic suite green (233/233); tsc clean. Implements the `finding` primitive (`PLANNING_ai_data_quality.md` §6b). → [agentic]
956. 🔧 Planning: **AI Data Quality Lifecycle** — one plan consolidating the rework-feature concept, the instance-flow/reconciliation plan, and the ai-runs-optimization ancestor, anchored on five operator pains (no review capacity; approved items decay; reviews repeat the same issues; intake/review split across time+people; no data overview). Reframed as a lifecycle (produce→grade→surface→triage→review/rework→re-grade) with six pillars: the KI-Runs **Workbench** (one surface), a **quality grade**, **Standards separated from schema** (fix for recurring review issues), **rework as the single execution arm** (levers L1–L5), **reconciliation** as one evidence source, **auto-approve** as the throughput valve. Diagnosed the spec-contract "smell" (one JSON file wears six hats, ungoverned; the capability-restructure orphaned `INTAKE_TO_SPEC` + mis-aimed auto-approve/sweeper) → Phase 0 un-overloads it. Surface-before-automation phasing. Superseded `PLANNING_rework_feature.md` + `PLANNING_instance_flow.md`. `docs/PLANNING_ai_data_quality.md`. → [docs-infra]
955. 🔧 Planning: **instance agentic flow** (compute/bootable devices only — the intake API's domain) — a `scope=instance` flow consumes intake evidence (structured scan + `memtest`/`SMART`/`battery` Phase-2 files; raw `dmidecode`/`lspci`/CPU-stress **not yet collected**) + `InstanceSpecs` and **reconciles** the device against its reference's web-derived data, producing a **reconciliation object** (evidence digest, field comparisons, findings, operator-gated proposed actions, informational data-quality score, status). It never mutates `item_refs` and **never auto-triggers a ref change**: findings are flagged, and an **operator approves** (one click) to enqueue the existing `rework` — human gate mandatory; auto-triggers deferred to post-MVP. Reconcile is **item-read-only** (writes only the reconciliation object + owned instance-spec fills), dual-path (inline + standalone `mode=reconcile`), backfillable via its own timestamp/version. Introduces `scope`/`measuredSignal` on the spec contract (compute subcategories, replaces the `INTAKE_TO_SPEC` map), run **history** via latest-row snapshot + append-only `agentic_run_history` (transcript jsonb; existing readers untouched), and a new **`KI-Runs` list type**. Reuse-vs-dedicated-flow to validate; **builds on the shipped snapshot/diff (#918), search-sources (#916) and grounding (#917) work** rather than duplicating it (instance-field history = extending `agentic_run_snapshots`, which defers instance fields today). MVP operator-initiated; UI + data inventories folded in. **Re-validated after the "new pipeline" contract work** (plan §17): spine holds but the `scope`-field idea is superseded — reference contracts were redefined around **capabilities** (RAM-Slots/Kapazität/Typ), so the revised plan uses a **separate instance-spec contract** + a Phase 0 to stabilize the mid-refactor reference contracts; `INTAKE_TO_SPEC` is now orphaned. See `docs/PLANNING_instance_flow.md` → [agentic]
954. ✅ **Rejected reviews now teach the next run.** On reject the wizard folds a concrete before→after correction diff (texts reworded, dimensions filled, specs changed/removed, price) plus notes into `LastReviewNotes` under a labelled header — which already flows into the next run's extraction/supervisor prompts and survives restart. Chosen over deriving lossy `bad_format`/`wrong_physical_dimensions` flags: a diff ("Höhe 26, removed spec *Marketing*, renamed to *Lenovo ThinkPad X200*") is richer and unambiguous, and it's guidance (supervisor still validates), not a hard overwrite. On approve nothing is emitted — edits are persisted, so corrected values are the next run's baseline. Frontend-only; new wizard tests cover it. Flag-based review metrics deferred. → [agentic]
