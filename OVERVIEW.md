## Recent changes (last 10)

953. ✅ Agentic review is now **inline-editable** for small fixes: steps 1 (Artikelbeschreibung) and 2 (Kurztext) still ask Ja/Nein, but answering *Nein* now offers a correction prompt instead of forcing a rejection. A corrected value resolves the mismatch (run stays approvable) and is sent as `referenceEdits` → persisted to `item_refs` on approval (new `applyReferenceEditsAfterReview`, whitelisted to Artikelbeschreibung/Kurzbeschreibung). Declining the correction preserves the original reject signal. → [agentic]
952. ✅ Hard-drive **dimensions fall back to standard form factors**. HDD/SSD measurements are rarely published, so runs left Länge/Breite/Höhe blank. `extract.md` now instructs the agent: when no explicit dimensions appear in sources, fill them from the drive's form factor — 2.5″ → 100/70/7 mm, 3.5″ → 147/102/26 mm — applied only when the form factor is stated/determinable, never for other product classes. → [agentic]
951. ✅ Shopware pre-merge **review fixes**: (1) net price was computed `== gross` whenever `SHOPWARE_DEFAULT_TAX_ID` was pinned (cached tax id but rate left 0) — `resolveTaxId` now only short-circuits once the rate is known, else fetches the pinned tax's own rate. (2) Deactivating a product or dropping a ref below 2 instances left **variant children active + in stock** (sellable) — new `deactivateVariantChildren` cascades `active:false, stock:0` on both the deactivation and single-product paths. Verified variants 14/14 (+ deactivation cascade) + full Shopware suite regression. → [erp-sync]
950. ✅ Event-log export/import round-trip no longer corrupts `Meta` into `[object Object]`. `events.Meta` is a `jsonb` column, so `pg` returns it to `export-data.ts` as a **parsed JS object**, but `toCsvValue` serialized cells with `String(value)` → the literal `"[object Object]"` in `events.csv`; on re-import that string was bound into the `jsonb` column → `22P02 invalid input syntax for type json`, and since `insertEventLogEntry` swallows the error the whole event row was silently dropped. Fixed at the source — `toCsvValue` now `JSON.stringify`s object/array cells (Date excluded) so the value round-trips — plus importer hardening: `sanitizeEventMetaValue` drops a non-JSON `Meta` to `NULL` (with a warning) so a row from an already-broken export still imports instead of being lost (mirrors the `initDb` legacy-Meta sanitization). → [erp-sync]
949. ✅ Intake can now match a booted device onto a **pre-existing instance** instead of forcing a duplicate. Items catalogued before the intake API have no serial/MAC, so `/start`'s identifier lookup misses and the operator was pushed to create a new item. Now each `select_ref` candidate carries `matchableInstances` (instances of that ref with no serial/MAC, excluding in-device components + zero-stock), and the `type:'ref'` answer accepts `useItemUUID` to bind the scanned serial/MAC + scan onto the chosen instance (guarded: must belong to the ref, must not already carry a different identity → 409; idempotent). Fully additive — a script that ignores the new fields behaves as before. → [intake]
948. ✅ Shopware properties: **push all Langtext, filter only spec-contract fields**. Pushing every Langtext key as a filterable property flooded the storefront filter sidebar. Now **all** keys are still pushed as properties, but a property group is created **`filterable`** only when its key is a recognized spec-contract field — `registry.getFilterableSpecKeys()` = the union of `contracts/specs/*.json` `fields[].key` (e.g. Prozessor/Display/Anschlüsse for laptops), threaded through the snapshot as `filterablePropertyKeys`. Freeform keys become **non-filterable** properties (still visible on the product). `ensurePropertyGroup(name, filterable)` also **heals** an existing group whose flag differs (PATCH), so over-filtered groups from earlier syncs flip to non-filterable and a changed contract re-filters next sync; same rule applies to variant-axis groups (itemUUID/Zustand → non-filterable). Flag is global per group (Shopware has no per-product filterable), so the whitelist is the contract union. Verified 7/7 (create filterable/non-filterable by spec membership, heal both directions, all keys still pushed, back-compat all-filterable) + property/variant/multiaxis regression. → [erp-sync]
947. ✅ Shopware sync: **product categories** linked from the ref's category codes. The snapshot resolves `Hauptkategorien_A/Unterkategorien_A` (+ the secondary `_B` pair) → Shopware category **display names** via the static `models/item-category-lookups` taxonomy (sub label + de-underscored main label, e.g. `Laptop_und_Zubehör` → `Laptop und Zubehör`); `adminClient.syncProductCategories` matches each name to an **existing** Shopware category (`/api/search/category` on `name`, cached — **never creates**, the tree is user-owned) and PATCHes `product.categories`. Additive (existing links preserved), unmatched names skipped (self-heal on re-sync), ambiguous names link the first + log. Verified 5/5 (link main+sub, skip unknown, first-of-ambiguous, cached, all-unmatched → no PATCH) + name-resolver 7/7 against the real taxonomy. Per operator decision: link-only to their existing categories, both A+B. → [erp-sync]
946. ✅ Fix Shopware **configurator 1062 recurrence** — reuse existing configurator-setting ids. #944's deterministic id stopped *new* duplicates but couldn't heal rows created before ids were set: a PATCH entry with a fresh id for an `(product, option)` that already has a row makes Shopware **INSERT** → `1062 Duplicate entry` on `uniq.product_configurator_setting` again (hit once the itemUUID axis was added, since the PATCH now carries options that already had rows). `syncVariants` now first searches `product-configurator-setting` for the parent, **reuses the existing row's id** per option (so the PATCH updates in place), gives only genuinely-new options a deterministic id, and deletes stale axes (404-tolerant). Verified 12/12 (added: existing option reuses its stored id, new option gets a deterministic id, stale axis deleted). → [erp-sync]
945. ✅ Shopware sync: **image previews render** + **itemUUID as the variant axis**. (1) **Blank previews:** uploaded product images showed no preview because `ensureMedia` created the `media` entity with **no folder** — unassigned media gets no thumbnail config, so Shopware never generates thumbnails. It now resolves the **Product Media** default folder once (`/api/search/media-folder` on `defaultFolder.entity=product`, cached) and sets `mediaFolderId` on create, so thumbnails/previews generate (falls back to unassigned if unresolved). (2) **itemUUID axis:** `buildVariantGroups` now adds each instance's `ItemUUID` as a variant option, so the signature is unique per instance → **one variant = one physical item** (instances no longer merge), letting the operator switch variants on `itemUUID` in Shopware and group the spec axes as descriptive. Consequence: any ref with **≥2 instances** is now a variant parent (spec-less instances included); a single-instance ref stays a plain product. Verified: grouping 6/6 (per-instance, no merge, itemUUID present) + images 8/8 (folder resolved+set, cached) + variants 9/9 regression. → [erp-sync]
944. ✅ Fix Shopware **variant re-sync 500** (duplicate configurator entry): `adminClient.syncVariants` PATCHed the parent's `configuratorSettings` with entries that had **no `id`**, so every re-sync re-inserted the same option rows and hit `uniq.product_configurator_setting` (product+version+option) → `1062 Duplicate entry` (500 = retryable ⇒ the manual Shop-Sync of an existing variant parent wedged in a retry loop). Each entry now carries a **deterministic id** (`sha1(parentId:optionId)`, same idempotency trick as product_media) so a re-sync upserts the same row by primary key instead of duplicating. Verified 9/9 (incl. new deterministic-id + identical-ids-across-re-sync assertions). The image `mkdir Permission denied` the operator also saw is a dockware container fs-permission issue (code already skips a failed image), and the variant-storefront grouping is a Shopware-side presentation concern — both out of scope here. → [erp-sync]
943. ✅ Shopware **image sync** (P3): product images uploaded as **binary** (mediator→Shopware only). `lib/shopware-media.resolveShopwareImageInputs` maps a ref's `Grafikname` (cover) + `ImageNames` (`|`-list) to on-disk files (folder = 6-digit Artikel_Nummer) with lazy byte loaders + deterministic media filenames. `adminClient.syncProductImages` (in `upsertProduct`, on the parent): `ensureMedia` searches `media` by fileName → reuse, else create empty media + `POST /api/_action/media/{id}/upload` (raw bytes); then PATCH `product.media` (deterministic product_media ids) with `coverId`=first. Variant children inherit parent media; a failed image is skipped. Verified 5/5 (create+upload / reuse / cover / link); regression intact. Validate the media m2n + coverId write on a live shop; stale-image removal + documents deferred (doc options in the changelog). → [erp-sync]
